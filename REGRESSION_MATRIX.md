# REGRESSION_MATRIX.md — 2.0 vs 3.0 Comparative Analysis & Fix Plan

| Feature | 2.0 Behavior | Current 3.0 Regression | Root Cause | Proposed 3.0 Fix |
|---|---|---|---|---|
| **Timetable Loading** | Instant load from Hive cache. No auth blocking. | Buffering / blank screen / delays waiting on network or auth. | Timetable render awaited or tied to `AuthRepository` status and SRU portal network request. | Implement cache-immediate `TimetableRepository`. Render cached data in < 100ms, sync in background. |
| **Authentication Coupling** | App worked without requiring active SRU portal session. | Timetable broke or bounced to login when session expired (approx 8 hrs). | App tightly coupled timetable rendering to active SRU session cookies. | Decouple `AuthState` from `TimetableState`. Expired auth retains cached data + subtle warning. |
| **Tab Navigation** | Fast switching between tabs. | Switching tabs causes UI jumps, recalculations, or re-fetching. | Each tab (`HomeTab`, `WeekTab`) maintains independent loading/calculation logic and timers. | Unify timetable data under a single reactive `TimetableRepository` shared by all tabs. |
| **Data Migration** | Smooth updates. | Old user data or corrupted session forced repetitive logins or broken state. | Migration tried to clear V2 credentials inside old Hive box without clean namespace isolation. | Complete namespace separation (`sru_timetable_v3_prefs`, `sru_timetable_v3_cache`). Hard reset of session state while preserving user preference integrity. |
| **Pull to Refresh** | Refreshed timetable or kept old data. | Failing refresh or network error could cause blank/error screen. | State wiped or error state directly replaced cached data. | Safe refresh: retain existing timetable on error, update atomically on success, non-blocking toast/banner on failure. |
| **AdMob Banner Requests** | Reasonable request-to-impression ratio. | Excessive requests (2.59K requests vs 823 impressions, ~3x discrepancy). | `AdBanner` disposed when switching to Profile tab and rebuilt when returning. Page rebuilds re-requested ads. | Centralized banner lifecycle in `AdService` keeping banner mounted and alive across tabs. |
| **Android Recents / Ads** | Returning from external links was reliable. | Blank screen or duplicate task when returning from external ad browser. | `AndroidManifest.xml` had `launchMode="singleTop"` instead of `launchMode="singleTask"`. | Update `launchMode` to `singleTask`. |
| **PWA Startup** | Simple web app. | Potential hang on startup waiting for Firebase / AdMob / network calls. | Heavy initialization in `main()` before rendering first frame. | Non-blocking microtasks for FCM, AdMob, and analytics; initial skeleton render immediately. |
| **Password Autofill** | Basic input fields. | User struggled to use Google/Apple password managers. | Missing standard `autocomplete` hints and semantic form inputs. | Standard autofill attributes (`username`, `current-password`, `one-time-code`). |
